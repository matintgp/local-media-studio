# Local execution and storage boundaries

1. Bind to 127.0.0.1 by default. Same-origin production UI/API; development CORS allowlist only. Validate Host and Origin for writes, with a local session/CSRF protection scheme. No wildcard CORS or unauthenticated LAN exposure. Do not publish a tunnel.
2. Engine endpoints are backend-configured allowlisted loopback services, not arbitrary URLs supplied to a generic proxy. Bound timeouts, redirect behavior, response size and outbound upload destinations. Do not forward credentials to redirected hosts.
3. Assets are addressed by IDs. Canonicalize every path and verify containment under configured allowed roots, including Windows case-insensitivity, UNC/device path rejection and symlink/junction resolution. Do not accept arbitrary paths in public media download routes. Test traversal and link escape.
4. New storage/cache/output/staging paths are explicit. On the owner's Windows machine default data root is B:/MediaStudio, but validate it exists/is writable and never fall back to C. Cloud demo uses an explicitly configured temporary root. Read-only engine output roots are separate from app-owned write roots.
5. Never delete or rewrite installed model files, engine environments, source assets or backups. Duplicate/cleanup actions state what will be copied/deleted. A deletion of library metadata is separate from physical deletion. No automatic physical cleanup outside app-owned staging/cache.
6. Preflight imports/renders against estimated bytes and configured minimum-free-space reserve, recheck while staging, handle a full disk without corrupting DB or source files. Inspect filenames and stream uploads with limits; don't trust MIME/extensions alone. Avoid archive extraction in MVP unless securely bounded.
7. FFmpeg commands use explicit executable path and argument lists, no shell interpolation. Build filters from validated numeric/enumerated fields. Supplied subtitles are validated local assets; no arbitrary FFmpeg protocols, user filters or remote input URLs. Limit duration, dimensions, upload size and job count.
8. An app workflow is a typed media recipe, never arbitrary Python/JS/shell. Comfy workflows come from vetted installed templates with allowlisted editable inputs. Node code installation/custom-node downloading is out of scope. Recipe imports must not elevate filesystem or network access.
9. Future API keys are stored backend-only in ignored local configuration/environment, never sent to the frontend or persisted in public jobs/logs/exports. Optional provider requests disclose which prompt/media leaves the computer and require explicit enabling. No analytics or automatic prompt uploads.
10. Cancelling an app request is not proof external generation stopped. Cancel only an owned external job. Comfy interrupt can affect a currently running user job; verify identity and do not issue blanket interruption/queue clearing. Use only discovered supported WanGP cancellation contracts. Unknown jobs retain GPU admission until reconciled or explicitly resolved.
